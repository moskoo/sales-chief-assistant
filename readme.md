# Sales Chief Assistant · 销售首席助理

<img src="assets/sales-chief-assistant-icon.png" alt="销售首席助理：对话罗盘图标" width="120" height="120">

面向销售人员、销售负责人、售前与客户经营团队的中文 Agent Skill。将客户资料、沟通记录和销售数据整理为有依据的判断、可使用的沟通内容与明确的下一步行动，覆盖获客、需求、报价、成交和客户经营。

采用 `SKILL.md` 与按需读取的 Markdown 手册组织内容，可安装到支持 Agent Skills 的工具。先按[安装与调用](#安装与调用)选择你的 Agent，再用[快速开始](#快速开始)中的示例体验。

| 项目 | 说明 |
| --- | --- |
| 技能名称 | 销售首席助理 |
| 技能标识 | `sales-chief-assistant` |
| 通用任务写法 | `请使用 sales-chief-assistant 技能，……`；各工具的快捷调用见安装部分 |
| 默认语言 | 中文，可按客户需要起草其他语言内容 |
| 主要使用者 | 一线销售、销售负责人、大客户经理、售前及客户经营人员 |
| 业务适配 | ToB / ToC，新客 / 老客，长周期 / 短周期，按实际场景选择流程 |
| 交付形式 | 指令、工作手册与输出模板；无必需执行脚本或模型绑定 |

基础文本分析不要求连接业务系统，也不需要为本包额外安装 Python。联网研究、CRM、邮件、日历和文件生成使用所在 Agent 的实际能力与权限；这些服务不包含在本仓库中。

## 安装与调用

选择手动复制或 Skills CLI 中的一种方式即可。只克隆源码仓库不会自动为所有 Agent 注册技能；安装时必须保留 `SKILL.md`、`references/` 及其中的相对目录结构。

### 方式一：手动复制完整技能目录

1. 下载并解压源码或技能包，找到直接包含 `SKILL.md` 的目录。
2. 选择下面的项目级或用户级目录，将完整技能内容放入名为 `sales-chief-assistant` 的子目录。
3. 检查最终入口为 `目标技能目录/sales-chief-assistant/SKILL.md`，同级还有 `references/`。不要只复制入口文件，也不要多套一层仓库文件夹。
4. 使用 Agent 的技能列表或选择器确认发现结果；必要时刷新或重新开始会话。

下表列的是**技能父目录**，均需在末尾添加 `/sales-chief-assistant/`。项目级目录相对于目标工作区；`~` 指运行该 Agent 的用户主目录。Windows 原生、WSL、SSH 和容器的用户目录可能不同。

| Agent | 项目级目录 | 用户级目录 | 加载与调用 |
| --- | --- | --- | --- |
| [Claude Code](https://code.claude.com/docs/en/skills) | `.claude/skills/` | `~/.claude/skills/` | `/sales-chief-assistant`，或由任务匹配加载 |
| [Codex](https://learn.chatgpt.com/docs/build-skills) | `.agents/skills/` | `~/.agents/skills/` | `$sales-chief-assistant`；CLI / IDE 可通过 `/skills` 或 `$` 选择 |
| [Cursor](https://cursor.com/docs/skills) | `.cursor/skills/` 或 `.agents/skills/` | `~/.cursor/skills/` 或 `~/.agents/skills/` | 在 Agent 输入框键入 `/`，选择技能 |
| [GitHub Copilot](https://docs.github.com/en/copilot/how-tos/copilot-on-github/customize-copilot/customize-cloud-agent/add-skills) | `.github/skills/` 或 `.agents/skills/` | `~/.copilot/skills/` 或 `~/.agents/skills/` | 在支持 Skills 的 Agent 界面按名称请求，由相关性匹配加载 |

| [Google Antigravity](https://antigravity.google/docs/skills) | `.agents/skills/` | `~/.gemini/config/skills/` | `/sales-chief-assistant`；旧版目录兼容以客户端为准 |

**本地与云端需要分别确认。** 用户级文件不会自动出现在所有云端、远程或自动化会话中。Cursor 的个人技能同步有专门设置；其他产品按其云端安装或仓库加载规则处理。OpenClaw 的工作区是其 Agent 配置的工作区，不一定是终端当前目录；自定义状态目录时以实际配置为准。

### 方式二：使用 Skills CLI

若已安装 Node.js 与 npm，可使用 [Skills CLI](https://github.com/vercel-labs/skills) 将同一份技能安装到多个 Agent。它是可选的第三方安装工具，不是运行本技能的依赖。

**从已经下载的源码安装**：在直接包含本技能 `SKILL.md` 的目录运行：

```sh
# 先列出可发现的技能
npx skills add . --list

# 安装到当前项目，在交互界面选择 Agent
npx skills add . --skill sales-chief-assistant

# 或安装到指定 Agent 的用户级目录
npx skills add . --skill sales-chief-assistant -a claude-code -a codex -g --copy
```

**从 GitHub 仓库安装**：将 `OWNER/REPO` 替换为本项目实际的 GitHub 仓库地址；这是占位符，不能原样使用。

```sh
npx skills add OWNER/REPO --list
npx skills add OWNER/REPO --skill sales-chief-assistant
```

- 不带 `-g` 时安装到项目级；带 `-g` 时安装到用户级。
- `-a` / `--agent` 选择适配目标，如 `claude-code`、`codex`、`cursor`、`github-copilot`、`gemini-cli`、`opencode`、`windsurf`、`antigravity`、`openclaw`、`qoder`。
- TRAE、CodeBuddy、Kimi Code CLI 等也可从安装器的当前列表选择；对应标识包括 `trae`、`trae-cn`、`codebuddy`、`kimi-code-cli`，以所用 CLI 版本支持范围为准。
- `--copy` 使用文件复制，可用于不便创建符号链接的环境。安装器选择的兼容目录可能与上表的原生目录不同。

若由安装器管理后续更新，沿用它的更新方式；手动复制的版本则重新合并或替换内容。安装器显示成功后，仍应在实际 Agent 中检查发现结果。

### 部分工具的原生安装命令

下面以“终端当前目录直接包含本技能 `SKILL.md`”为前提。选与你使用的工具对应的一组即可：

```sh
# Gemini CLI：安装到用户级，再检查
gemini skills install . --scope user
gemini skills list

# OpenClaw：安装到当前配置的 Agent 工作区，再检查
openclaw skills install .

```

### 安装后的验证

先通过工具本身的技能列表、选择器或快捷命令确认 `sales-chief-assistant`，再提交：

```text
请使用 sales-chief-assistant 技能。
先读取 SKILL.md，再说明客户沟通分析和报价测算分别会读取哪些手册。
只列文件名及用途，先不执行外部操作。
```

应能实际读取入口和相关文件，包括 `references/playbooks.md`、`references/revenue-metrics.md` 与按需的 `references/templates.md`。仅回答“我能担任销售助理”不足以证明技能已安装。

### 不支持原生 Skill 的助手

可以将入口和任务相关手册提供给能够读取文件的助手，并明确要求按其执行。这属于手动提供指令；不会注册快捷命令，也不会带来永久记忆、CRM 连接或定时运行能力。只粘贴 `SKILL.md` 而不提供相关手册时，流程可能不完整。

## 快速开始

### 第一步：选一个眼前任务

安装并确认技能可用后，可以从“回复一条客户消息”“准备一次拜访”或“把会议记录变成行动项”开始。只提供与该任务有关的产品事实、客户原话和期望产出即可，不必先建立完整客户档案。

### 第二步：提供事实和要求

下面是可直接试用的虚构场景。示例统一使用自然语言指定技能；需要显式快捷调用时，用所选 Agent 的 `$`、`/` 或 `@` 选择技能，再附上同一段任务。实际使用时替换为自己的信息。

```text
请使用 sales-chief-assistant 技能，帮我处理一位客户的价格异议。

产品：企业客户跟进工具。
已确认能力：记录跟进任务、生成会议纪要草稿。
价格：标准报价 12 万元/年，尚未授权任何折扣。
客户：一家企业的业务主管，预算和最终审批人未知。
客户原话：“12 万有点贵，而且我担心买了以后业务员也不用。”

请输出：
1. 已知事实、可能解释和待核实项。
2. 一条 100 字以内、适合微信发送的自然回复。
3. 下一次最值得问的一个问题，以及需要准备的材料。

不要假设客户没有预算，也不要承诺试用、折扣或部署周期。
```

### 第三步：检查结果并补充信息

合适的结果应识别“价格顾虑”和“使用落地顾虑”，将价值是否清晰作为待验证解释，保留预算与审批人的未知状态。

一种可能的回复草稿是：

> 确实需要把投入和实际使用看清楚。您团队过去用类似工具时，最难坚持的是哪一步？我可以先按这个场景整理一页流程对照，方便您判断是否值得继续评估。

收到客户新回复后继续补充：

```text
补充客户的新回复：[原话]。
请更新判断，说明哪些推断已得到验证、哪些仍未知，再给下一条回复。
```

这类反馈能让方案随着真实沟通推进。不要把第一轮分析当成固定结论。

## 能力范围

### 四类核心能力

| 能力 | 具体作用 | 常见产出 |
| --- | --- | --- |
| 软技能 | 同理心、情绪承接、积极倾听、按角色沟通、面对拒绝后的复盘 | 客户顾虑分析、自然回复、沟通反馈、陪练 |
| 销售硬技能 | 获客、需求挖掘、价值呈现、异议处理、谈判成交、客户经营 | 客户卡、拜访提纲、跟进计划、报价、双方行动计划 |
| 技术与 AI 技能 | CRM 信息整理、漏斗与预测、纪要、意向信号、远程演示、PoC、RFP | 字段映射、商机分析、会议行动项、演示与验证方案 |
| 商业理解 | 理解行业与客户流程、成本收益、预算周期、关键人和决策链 | 商业论证、ROI / TCO 测算、大客户关系地图、经营简报 |

### 可按需展开的工作

- **客户开发**：确定理想客户、筛选线索、分析触发信号、设计接触切入点。
- **转化推进**：客户分层与标签、跟进序列、冷邮件、异议回应、报价组合和成交表达。
- **销售内容**：角色消息地图、竞品作战卡、发现简报、异议应答卡、活动线索交接。
- **客户经营**：健康趋势、续约风险、复购、沉睡唤醒、增购与自愿转介绍。
- **负责人工作**：事项排序、资源请求、周度复盘、销售预测和团队反馈。
- **行业适配**：房产、外贸与制造业、本地服务、咨询与专业服务、社区及社交渠道。

建议围绕一次具体决策使用。比如“本周优先推进哪些机会，依据是什么”比“帮我提升销售业绩”更容易得到可执行结果。

## 首次配置

先准备一份轻量业务说明。下面的项目按任务填写，未知项写“未知”或“待确认”。无需一次补齐。

```text
请使用 sales-chief-assistant 技能，按以下业务背景处理本次及后续相关任务。

销售模式：[ToB / ToC，直销 / 渠道 / 私域等]
产品或服务：[一句话说明]
目标客户：[行业、规模、角色与适配场景]
核心问题：[客户通常需要改变什么]
已确认能力：[当前确实能够提供的内容]
产品限制：[暂不支持或需要额外条件的部分]
定价：[金额、币种、含税口径、计费周期]
让步权限：[已批准的优惠或交换条件；没有则写无]
交付条件：[客户配合、交期、实施依赖]
可用证据：[产品资料、可使用案例、演示或验证结果]
实际销售阶段：[沿用本公司的阶段名称与含义]
目标与期间：[签约 / 确认收入 / 回款，分别说明]
可用工具：[联网、CRM、邮件、日历等；未连接也请说明]
输出偏好：[简短 / 详细，文案 / 表格 / 报告等]
本次任务：[这次要解决的问题]
```

产品资料有更新时，指出旧内容和新内容的差异。已有业务配置能在当前上下文复用；是否能跨聊天保存取决于环境，不应默认具备永久记忆。

### 写清一次任务的五个要素

```text
请使用 sales-chief-assistant 技能。
目标：[希望客户或团队作出什么决定]
事实：[当前产品、客户、阶段和真实约定]
材料：[聊天原文、笔记、文件或数据]
产出：[要什么成品，给谁用，多长]
边界：[报价权限、不可承诺事项、是否仅起草]
```

例如，要求“给采购看的单页价值说明”和“给销售经理的内部风险分析”，会得到不同的内容。需要两版时明确区分受众，避免把内部底价或竞争策略混入客户文案。

## 场景使用指南

下面的示例均为可替换模板。方括号内填实际材料；固定示例数字仅用于演示。

### 1. 潜在客户研究与接触准备

**准备**：产品、目标行业和地区、适配及排除条件、已有客户经验。需要真实目标公司时说明研究范围；联网不可用时可先整理你提供的名单。

```text
请使用 sales-chief-assistant 技能，为[产品]研究[地区 / 行业]潜在客户。
理想客户条件：[条件]；排除条件：[条件]。
请输出候选清单、适配理由、可核验的需求信号、拟接触角色、
切入点和待核实项。若无法联网，只分析我提供的名单，不虚构公司。
```

**检查**：适配度与购买意向是否分开；联系人和联系方式是否真实；行业现象是否被误写成该客户已发生的问题。

### 2. 拜访准备与需求挖掘

**准备**：会谈目标、参会者角色、已知流程、客户原话及当前疑问。

```text
请使用 sales-chief-assistant 技能，为与[客户 / 角色]的[时长]会谈准备提纲。
已知信息：[材料]；本次目标：[目标]。
请先列事实与假设，再安排开场、自然追问和收尾。
围绕现状、问题、影响和改善价值组织提问，
复杂决策条件只补与这次会谈有关的部分。
```

**应得到**：会前判断、关键问题、相关材料和适合当前阶段的下一步邀请。问题应沿回答展开，不应变成机械盘问。

### 3. 异议回应与情绪处理

**准备**：客户完整原话、报价或服务事实、之前怎么回复、可用处理权限。

```text
请使用 sales-chief-assistant 技能，分析这条异议：[原话]。
背景：[产品、价格、阶段、已有沟通]。
先区分可能顾虑与待验证项，再给一版[微信 / 电话 / 邮件]回复，
附一个澄清问题和下一步。若涉及投诉，先回应具体影响与处理安排。
不要自行承诺优惠、赔偿或未来功能。
```

**检查**：回应是否真正处理问题；有没有把拒绝都解释为购买信号；案例、保障和时限是否有依据。需要比较表达时，可另要求“给共情澄清、证据说明、开放提问三种版本”。

### 4. 跟进计划与冷邮件序列

**准备**：客户状态、已做动作、销售周期、沟通约定、当前可提供的新信息。

```text
请使用 sales-chief-assistant 技能，为[客户 / 客群]设计[期间]跟进计划。
客户状态：[内容]；已做动作：[内容]；联系约定：[内容]。
每次列目的、新增价值、渠道、完整草稿、一个行动请求，
并写出积极回应、犹豫、无回应后的分支与暂停条件。
只起草计划，不发送、不加入自动化序列。
```

**应得到**：有新价值的触点安排，节奏随客户反馈调整。21 天只是一种可选计划长度；长周期项目可按评审、预算和采购事件安排。

冷邮件可补充“给两个真实具体的主题行，每封独立成篇”。已有数据时再要求诊断送达、正向回复或合格机会形成的问题。

### 5. 报价组合与可测试交付包

**准备**：需求、真实产品或服务范围、成本、报价权限、交付与付款条件。

```text
请使用 sales-chief-assistant 技能，为[需求]设计报价。
可提供内容：[内容]；成本与已批准价格：[内容]；权限：[内容]。
如确有适用差异，给基础、推荐和扩展三个方案；不必强凑三档。
客户版写清输入、交付物、验收、费用、周期、修改次数和不包含项。
内部版另列毛利、让步条件和待审批事项。
```

**检查**：每档是否真实适配；一次性与持续费用是否清楚；推荐理由是否对应客户需求；内部信息是否与客户版分开。

咨询服务可增加：“先设计一个小范围测试包，用明确产物和验证结果决定是否扩大范围。”

### 6. 价值论证、ROI 与 TCO

**准备**：观察期间、币种、现状成本、新增投入、可兑现收益与关键假设。

```text
请使用 sales-chief-assistant 技能，做一份首年商业价值说明。
以下为演示输入：现金成本节约 12 万元，新增毛利 6 万元，
一次性投入 3 万元，首年持续投入 5 万元，均为人民币。
收益已按采用条件调整，假设按月均匀发生，一次性投入在期初。
请列计算式、ROI、简化回收期及限制；另说明真实测算要补哪些数据。
不要把节省工时自动计入现金收益。
```

**核对演示结果**：首年收益 18 万元、投入 8 万元、净收益 10 万元，ROI 为 125%；在上述均匀现金流假设下，简化回收期约 2.77 个月。真实客户必须替换为实际输入。

TCO 用于比较相同期间的总拥有成本；TCO 差额与项目 ROI 不能混用。缺少收益兑现证据时可先列估算模型及取数问题。

### 7. 大客户关系地图与成交推进

**准备**：项目背景、已接触角色、角色原话或行动、采购与审批情况、替代方案。

```text
请使用 sales-chief-assistant 技能，为[商机]整理关系地图和双方行动计划。
资料：[内容]。
标明已确认角色、推断角色、缺失接触与主要阻碍；
比较高层发起和使用团队试点两条路径的条件。
行动计划写双方负责人、前置依赖、目标时间和完成证据，
客户未答应的内容标“拟议”，没有约定时间则保留“待约定”。
```

**检查**：是否把联系人热情误当决策权；是否有客户侧完成标志；下一步是否真正解除当前阻碍。

### 8. 客户会议转行动计划

**准备**：原始笔记或转录、参会人、会议日期、时区，以及纪要面向内部还是客户。

```text
请使用 sales-chief-assistant 技能，整理以下会议记录：[材料]。
会议日期与时区：[内容]；读者：[内部团队 / 客户]。
输出简短摘要、已作决策、行动项和遗留问题，再起草跟进消息。
行动项包含负责人、截止时间、状态和完成标志；未明确的内容待确认。
客户版不包含内部底价和内部竞争策略。先不发送或创建任务。
```

**应得到**：讨论建议与已作决策分开，决策有对应人员，任务有具体动作。转录没有提到的负责人或期限不能直接补成事实。

### 9. CRM、销售漏斗与预测

**准备**：CRM 导出、统计截止时间、目标期间、金额口径、阶段定义。分析转化率还需要阶段变更记录或可比较队列。

```text
请使用 sales-chief-assistant 技能，分析我提供的 CRM 数据。
截止时间：[日期、时区]；目标期间：[起止日期]。
目标口径：[签约 / 确认收入 / 回款]；金额单位与币种：[内容]。
阶段定义：[内容]；数据性质：[当前快照 / 含阶段变更历史]。
请输出数据质量问题、本周优先机会、关键风险和预测依据。
没有可靠期间内成交概率时，给条件明确的情景，不自设阶段概率。
```

**检查**：当前阶段存量是否被误叫转化率；赢单与在途是否重复；不同币种、ARR、合同额是否混加；预测期间是否与成交概率含义一致。

若需要更新系统，下一轮明确指定客户或商机、字段、变更值和执行范围；只做分析不会自动写入 CRM。

### 10. 客户分层、标签与复购唤醒

**准备**：客户或匿名代号、购买历史、最近互动、正常复购周期、满意或投诉情况、可用权益及成本。

```text
请使用 sales-chief-assistant 技能，为以下客户制定分层运营计划：[材料]。
业务目标：[复购 / 风险干预 / 潜力培育]；复购周期：[内容]。
按可用数据设计分层与标签，说明准入、升降层和更新条件，
列各层动作、个性化草稿、停止条件和效果指标。
没有订单记录的客户不要硬算 RFM，权益只能用已授权选项。
```

**应得到**：可以维护的规则与客户名单，而不只是 S/A/B/C 标签。沉睡与流失风险需区分，有投诉的客户先处理体验问题。

### 11. 销售内容与竞品作战卡

**准备**：产品事实、买家角色、商机阶段、比较标准、可用证明与表达要求。

```text
请使用 sales-chief-assistant 技能，为[买家角色 / 商机阶段]制作[内容类型]。
客户当前问题：[内容]；已确认产品资料：[材料]。
请把问题、价值、证据和一个下一步对应起来。
若做竞品卡，统一版本和比较条件，未知项保留，不编造竞品缺陷。
```

**可选成品**：角色消息地图、竞品作战卡、会前简报、异议应答卡、活动交接单。团队复用时标明适用产品版本、负责人和使用状态。

### 12. 远程演示、PoC 与 RFP

**准备**：客户任务、参与角色、已知产品能力、验证环境与资料，以及原始需求编号。

```text
请使用 sales-chief-assistant 技能，为[客户场景]准备[演示 / PoC / RFP]。
已知需求与产品事实：[材料]；资源和时间条件：[内容]。
演示按输入、操作、输出和业务意义组织。
PoC 列范围、基线、建议验收指标、责任和退出条件；未确认阈值标拟议。
RFP 逐条保留编号，区分已支持、部分支持、不支持和待确认。
```

**检查**：演示成功是否被误当生产就绪；计划能力是否被误写为现有能力；未知技术参数是否已安排合适的人核实。

### 13. 首席助理简报与周度复盘

**准备**：当前目标、商机变化、客户约定、资源限制和待决定事项。

```text
请使用 sales-chief-assistant 技能，根据以下资料整理[今日简报 / 本周复盘]。
资料：[内容]。
先列最需要决定的事项，再给少量优先动作，解释为什么现在做。
每项写负责人、时间性质、完成标志与所需支持。
周报另列目标、已实现、预测依据和较上期变化；缺失数据明确保留。
```

**应得到**：客户购买动作与阻碍的变化，而不是发送次数清单。只有本次资料时，助手提供本次简报；持续推送需要另行设置可用的定时功能。

### 14. 复盘与销售陪练

**准备**：实际对话或模拟角色、销售阶段，以及一项训练目标。

```text
请使用 sales-chief-assistant 技能，扮演[客户角色]，陪我练习[具体目标]。
场景：[产品、阶段和客户背景]。
每轮只给一次客户反应，等我回复再继续；我说“结束陪练”后，
按同理、倾听、价值、回应和推进给有行为证据的反馈，
指出最值得改进的一两处，并给替代表达。
```

**检查**：反馈是否引用实际行为；纯文字材料不应评价语气、音量或表情。没有可靠时间信息时，不能把字数占比叫作说话时长比例。

### 行业场景怎样选择

保留通用调用方式，将下面的场景要求加在任务后。行业资料只需提供与这次决策相关的部分。

| 场景 | 优先提供 | 可直接追加的要求 |
| --- | --- | --- |
| 房产市场比较、预约与带看 | 房源属性、成交与在售记录、客户标准、联系方式、时间与时区 | “区分成交价和要价，列比较缺口；预约只有收到明确答复才标已确认；带看如实说明缺点。” |
| 外贸与制造业 | 产品规格、用途、数量、目的地、语言、供货及计价条件 | “按信息齐全、待补、需核验、不适配整理询盘，起草多语种回复，列人工接手条件。” |
| 本地服务 | 漏接或咨询记录、营业与服务资料、处理权限 | “先设计单渠道的分类、草稿和人工确认流程，给处理状态与复盘指标，不自动报价。” |
| 咨询与专业服务 | 客户要解决的流程、已有材料、可交付范围、费用与修改条件 | “把服务设计为可检查的结果包，写明客户输入、验收、修改范围和不包含事项。” |
| 社区与社交渠道 | 公开讨论、产品事实、社区参与规则 | “筛选尚未解决且真实适配的问题，给有实质帮助的回复草稿和待处理队列，不直接发布或私信。” |

若一个任务跨多个场景，先说明主要目标。例如“外贸询盘后的价格异议”可以先分析异议，再按外贸的单位、币种和交付条件校对回复。

## 资料与数据准备

### 哪些材料最有帮助

| 任务 | 优先准备 | 缺少时怎么做 |
| --- | --- | --- |
| 回复与异议 | 完整原话、上下文、产品和处理权限 | 先写中性求证回复，保留未知项 |
| 获客与拜访 | 产品适配条件、目标范围、已有研究 | 分开列事实与假设，安排待查问题 |
| 报价与价值 | 成本、价格、范围、投入收益与兑现条件 | 先交方案结构和取数清单 |
| 大客户推进 | 已接触角色、决策流程、真实客户动作 | 先绘制已知关系与待验证缺口 |
| 数据分析 | 去重标识、阶段、金额、日期和口径 | 限定结论范围，不补造历史与概率 |
| 客户经营 | 购买或服务记录、互动、体验与周期 | 用定性规则，标明健康判断的不确定性 |

直接粘贴文字、上传宿主支持的文件，或提供已授权可访问的资料即可。文件能否解析由所在环境决定；无法读取时可以提供相关文本或导出为可读表格。

### CRM 数据字段建议

| 分析目的 | 需要的主要字段 |
| --- | --- |
| 当前机会排序 | 商机 ID、客户、负责人、实际阶段、金额与币种、预计成交日、最近客户动作、下一步 |
| 转化与周期 | 上述字段，加创建日、资格确认日、阶段变更时间、实际结案日、赢单 / 输单状态 |
| 期间预测 | 金额指标、目标期间、已实现额、期间内成交概率及其依据，或支持情景判断的决策条件 |
| 客户健康 | 同期使用或服务采用、互动、支持问题、关键关系、合同与商业变化；有上期数据更便于看趋势 |

提交时说明一行代表客户、联系人、商机还是订单；同一客户多个商机不能随意合并。日期建议使用 `YYYY-MM-DD`，涉及具体时刻时同时注明时区。

仅提供必要的业务信息。示例、跨客户复盘和问题库使用匿名代号，移除与任务无关的手机号、身份资料、账号密钥和合同机密。不要为了让表格看起来完整而填写猜测值。

## 输出与执行规则

### 默认输出怎样阅读

复杂任务通常按下面的顺序组织，简单任务可直接给成品：

1. **当前判断**：最主要的机会、顾虑或阻碍。
2. **依据与缺口**：事实、推断和待核实项分别说明。
3. **可用成品**：回复、提纲、报价、计划或分析表。
4. **下一步**：谁做什么、何时做、怎样确认完成。

事实是材料能支持的信息；推断需要说明依据和验证方法；缺少或相互冲突的信息保留为待核实。对外文案会整理为自然表达，内部分析标签不必发给客户。

### 工具与授权

| 工作 | 基础条件 | 状态应该怎样理解 |
| --- | --- | --- |
| 分析材料、改写文案、起草计划 | 助手能读取输入 | 得到分析或草稿，可继续修改 |
| 查最新公司或行业信息 | 实际可用联网工具 | 只能根据真实检索结果说明已查到什么 |
| 读取 CRM | 已连接且有读取权限 | 以真实返回记录为准；导出分析也可开展 |
| 更新 CRM | 明确的执行请求、对象、字段和范围，以及可写工具 | 区分待写入、成功、部分成功与失败 |
| 发邮件、消息、拨号 | 明确授权的对象、渠道和内容，且有执行工具 | 草稿与已发送分开，不能凭生成内容声称完成外发 |
| 建日程或定时任务 | 明确时间、时区、对象与执行范围，且有相应工具 | 拟议安排与已创建事项分开 |
| 折扣、退款、保障或交付承诺 | 已确认的商业权限与条件 | 没有权限时只能提出待批准建议 |

已授权且范围明确的操作无需重复确认。接收对象、内容、金额或执行范围不清时，先补齐关键条件。失败后先核对实际状态，再考虑重试，避免重复写入或外发。

### 怎样检查结果是否可用

- 客户原话与助手解释是否分开，关键结论是否有依据。
- 方案是否对应当前产品能力、客户场景与决策阶段。
- 金额、期间、单位、币种和收益条件是否一致。
- 给客户的文案是否泄露内部信息或承诺未经批准的内容。
- 下一步是否有对象、动作和完成标志，拟议安排是否标明。
- 客户拒绝、验证失败或条件不适配时，是否有合理的调整或结束方式。

## 日常工作方式

| 时机 | 推荐任务 | 带入材料 | 得到什么 |
| --- | --- | --- | --- |
| 开始工作时 | 确定今天最值得推进的事项 | 客户约定、商机变化、待办与资源限制 | 优先动作、风险和支持请求 |
| 会前 | 准备一次有效对话 | 已知事实、参会角色、会谈目标 | 提问、证明材料和收尾邀请 |
| 会后 | 把共识转为行动 | 笔记或转录 | 决策、行动项、对外跟进草稿 |
| 客户回复后 | 更新判断与下一句 | 新回复和原计划 | 变化说明、回应、下一步 |
| 周度复盘时 | 统一看目标与商机 | 同口径数据和上期状态 | 漏斗变化、风险、预测依据与改进 |
| 交付或续约节点 | 验证客户价值 | 实际使用、结果、问题与合同节点 | 健康判断、改进、复购或续约动作 |

首次试用可挑一段对话、一次会前准备和一份会后纪要，检查是否减少遗漏、改善表达、让下一步更明确。形成稳定习惯后再扩大到团队材料或批量分析。

## 常见问题

### 找不到技能怎么办？

先对照安装表确认客户端版本、项目或用户作用域、实际运行环境以及 `SKILL.md` 的位置。用工具提供的刷新命令、选择器或新会话检查，必要时再重启。若装有多份同名技能，核对实际读取的路径及覆盖顺序。

### 为什么其他工具不识别 `$sales-chief-assistant`？

`$` 不是统一的 Agent Skills 调用协议。Codex 可用 `$sales-chief-assistant`，Claude Code 可用 `/sales-chief-assistant`，Windsurf 使用 `@` 提及。按安装表选择相应入口，或在已安装前提下用自然语言请求使用该技能。

### 为什么本机能用，云端或远程会话找不到？

两者不一定共享文件与技能目录。确认文件已进入实际执行环境，或按客户端支持的同步、仓库安装方式提供。不要仅因为本机存在技能文件就假定云端会自动加载。

### Skills CLI 提示找不到技能怎么办？

本地安装时，确认当前目录或传入路径包含本技能 `SKILL.md`；远程安装时，将 `OWNER/REPO` 换成真实仓库，并先运行 `--list`。若技能位于单体仓库的子目录，可传入该目录或对应的 GitHub 目录 URL。

### 是否需要安装 Python 或编写程序？

本包以 Markdown 指令和模板为主，没有必需的执行脚本。围绕文字材料做分析与起草不需要为本包额外安装 Python。大文件处理、制表或其他操作是否需要运行工具，由实际任务和宿主环境决定。

### 是否必须连接 CRM、邮件或日历？

不必。未连接时仍能分析你提供的资料，产出字段映射、待写入记录、消息草稿和安排建议。连接工具后，再按实际权限处理执行任务。

### 为什么助手还会提问？

预算、范围、产品能力或执行对象等缺口可能改变方案。它应优先交付能完成的部分，只追问最影响当前判断的问题。可以补充：“先做已知部分，最多问三个关键问题，其他缺口列出即可。”

### 输出太泛或太长，怎么调整？

指定受众、渠道、长度和一个具体目标。例如：“只给适合微信的一版回复，80 字以内，附一个求证问题。”或“只列本周三项优先动作，解释排序理由”。同时补入客户原话和真实业务限制。

### 能不能直接判断客户一定会买？

购买意向只能根据真实信号与决策条件判断，不能保证结果。客户称赞、问价或下载资料不等于即将成交；预算、审批、采购和下一步承诺仍需验证。

### 为什么没有给精确成交概率或客户健康分？

精确数字需要可解释的尺度、数据与校准依据。没有可靠概率时会给情景判断；没有评分规则时可以先定义指标和权重，并说明是假设方案。健康评分不等同于续约概率。

### 所有客户都要用 21 天跟进计划吗？

不需要。跟进围绕销售周期、客户反馈与实际事件安排。短周期客户可更短，复杂项目可按评审和采购节点推进；明确拒绝或要求停止后应结束触达。

### 通话一定要达到某个说听比例吗？

技能关注是否理解客户、确认信息并获得有效需求。会谈类型和目标不同，不设统一比例。纯文字转录没有可靠时长信息时，只能讨论文字或行为，不能得出准确发言时长比例。

### 它会自动记住所有客户、每天主动发简报吗？

不能默认如此。当前资料可在可用上下文中复用；跨聊天保存、持续监控和定时推送需要环境支持与明确设置。生成一份每日工作建议不代表已经创建自动运行任务。

### 如何拿到表格、文档等文件？

在任务中说明所需格式、用途和字段。宿主具备相应文件能力时，可进一步生成；否则先取得清晰的文本或表格内容。本包本身没有随附专用文件生成程序。

### 怎样把客户反馈变成更好的结果？

补充实际发生的回复或行动，要求更新判断并说明变化。对无效建议指出具体原因，例如“这个角色没有预算权”“客户不接受邮件沟通”“功能尚未支持”。让修订依据真实信息，而不是只要求“更有说服力”。

## 自定义与维护

### 一线使用者

优先在业务配置和当前任务中调整产品、客户、渠道、价格、授权与输出要求，不必修改技能文件。将某次客户的特殊条件留在该客户材料中，避免影响其他业务。

### 团队使用者

先统一产品事实、报价权限、销售阶段、收入指标和交接口径，再复用模板。将可公开案例与内部材料区分，标明适用版本和负责维护的人。多人使用同一套规则时，定期收集实际误判、返工与客户反馈再修订。

### 技能维护者

| 想调整的内容 | 优先修改位置 |
| --- | --- |
| 角色定位、任务选择、共同行为和执行边界 | `SKILL.md` |
| 需求、异议、谈判、大客户与陪练方法 | `references/playbooks.md` |
| 分层、跟进、报价、销售内容和复购流程 | `references/conversion-workflows.md` |
| 行业专用输入、流程和判断条件 | `references/scenario-adapters.md` |
| 指标、公式、金额与预测规则 | `references/revenue-metrics.md` |
| 成品栏目与填写结构 | `references/templates.md` |
| Codex 界面名称、简介与默认调用提示 | `agents/openai.yaml`；其他 Agent 的元数据行为按各自规范处理 |
| 面向使用者的说明与示例 | `readme.md` |

修改时保留有效的技能标识与入口元数据；重命名文件后同步修正链接。新增行业方法时提供适用条件，不让所有任务默认读取。

更新前保存有意维护的自定义内容，将改动合入同一份技能，再同步交付包和实际使用目录。客户名单、真实聊天记录、密钥和内部报价不应混入通用分发包。

更新后挑与改动直接相关的任务检查效果：例如修改数据口径后检查计算与缺失处理，修改输出模板后检查栏目是否可用。说明文字更新后检查文件链接、示例与当前技能是否一致即可。

## 参与贡献

欢迎通过 Issue 报告问题、补充可复现的使用场景，或通过 Pull Request 改进指令、模板和安装说明。

- 报告安装问题时，注明 Agent 名称与版本、操作系统、安装方式、项目或用户作用域，以及实际目录结构。
- 报告行为问题时，提供脱敏的最小输入、期望结果和实际结果，说明相关产品或业务限制。
- 修改工作方法时，说明适用条件和可观察的改善；不要把单次客户经验变成所有场景的硬性规则。
- 提交安装适配时，区分官方文档核对与实机验证，并说明测试的工具版本。

不要在公开 Issue、PR 或示例中提交真实客户身份、合同、内部底价、账号密钥或未经允许公开的业务记录。

## 术语速查

| 术语 | 在本技能中的含义 |
| --- | --- |
| ICP | 理想客户画像：适合谁、为什么适合，以及排除条件 |
| SPIN | 用现状、问题、影响、改善价值组织需求对话 |
| MEDDPICC | 为复杂商机核对价值指标、经济决策者、决策标准与流程、签约流程、痛点、支持者和替代选择 |
| LAER | 倾听、承接、探索、回应；回应后验证顾虑是否解决 |
| MAP | 双方行动计划：共同里程碑、责任、时间、依赖与完成证据 |
| CRM | 客户关系管理系统及其中的客户、联系人、商机与互动记录 |
| ROI | 投资回报率：在明确期间和口径下比较收益与投入 |
| TCO | 总拥有成本：同一观察期内使用方案所需的总体成本 |
| RFM | 最近购买时间、购买频次、购买金额，用于有相应数据的客户分层 |
| PoC | 概念验证：在有限范围内检验方案与成功条件 |
| RFP | 客户的方案或采购需求文件，需要逐项回应能力与限制 |
| ARR / TCV | 年化经常性收入 / 合同总额，两者不能直接混加 |
