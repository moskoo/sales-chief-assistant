# 转化与客户运营手册

用于客户画像、分层标签、跟进序列、成交表达、报价组合、销售内容及老客运营。按当前任务选择相关部分，沿用主指令中的事实、承诺和执行边界。

## 1. 客户画像与个性化诊断

从沟通记录识别三层信息：客户明确要求的功能或服务、希望改变的业务处境、表达过的情绪与风险顾虑。每层对应原话；未说出的动机只作待验证假设。不根据年龄、地域或职业推定购买力和性格。

用客户在本次交易中的行为调整沟通，如“希望先看数据”“需要同事参与”“担心变更风险”，不把一次行为固化为人格类型。购买能力主要看已确认预算、支付安排与审批条件。

需要咨询式获客时，用经核实的产品资料或方法论设计少量诊断问题，再根据回答输出差距、建议与适配判断。相同回答应得到一致的事实判断，建议随真实输入变化；不为增强说服力编一个精确分数。

诊断结果只保留有用模块：当前状态、主要障碍、优先行动、适配方案和下一步邀请。允许“不适合本产品”的结果，避免每份报告都导向最高价方案。

## 2. 客户分层与标签

先确认运营目标和可用数据，再选维度。新线索看适配、需求与决策行为；老客户可用 RFM：最近购买时间（R）、购买频次（F）、金额（M），结合实际复购周期。缺少订单数据时不能伪造 RFM。

可从四类开始：重点维护、潜力培育、沉睡待唤醒、流失风险。沉睡表示互动或购买中断，风险表示已有不利信号，二者可重叠；明确主层级与辅助标记，防止重复统计和重复触达。

每层给出准入与退出条件、客户数量或未知项、服务目标、资源安排、渠道、建议频率和停止条件。人数来自名单计算，样本占比不能直接当全量人数。不要套用固定“二八贡献”结论。

标签优先覆盖来源、需求、意向、生命周期。每个标签写明定义、触发事件、负责维护的人、更新或失效条件，以及会改变的下一项动作。先保留能维护的少量标签；用微信备注、企业微信或既有 CRM 均可。

对存量客户按当前机会与风险分批补标，新客户在首次有效沟通后更新。定期检查标签冲突、过期意向和层级升降；不要把意向分层当成客户价值或成交概率。

## 3. 分阶段跟进与冷邮件

跟进分为建立理解与信任、补充价值与证据、协助决策三个目的，按客户实际进展推进。用户需要时可给 21 天示例计划；天数和次数都随销售周期、客户反馈及约定调整，不强行在第 21 天促单。

每个触点包含：时间或触发条件、渠道、新增价值、一段可用话术、单一行动请求，以及积极回应、犹豫、无回应三种后续分支。补充内容与当前问题相关，不用节日问候充当购买理由。

客户表达兴趣时承接其下一项问题；仍犹豫时验证缺口；无回应时仅在有新价值且符合约定时再联系，逐步降低频率。明确拒绝或要求停止则关闭触达，不跨渠道继续追逐。客户条件变化时重新规划。

冷邮件按三种任务交付：

- **首封**：明确发件身份、受众、触发点、可证明价值和一个低负担请求；需要时提供少量真实、具体的主题行。
- **序列**：每封只承担一个新角度，如相关证据、业务洞察、问题澄清、征询合适联系人或体面收尾；正文能独立理解。
- **诊断迭代**：区分未送达、无有效回复、未形成合格机会和机会未推进的问题。一次优先检验一个变量，不把打开率当唯一质量指标。

篇幅和术语根据角色、语言与渠道调整。个性化必须与业务问题有关；禁止假转介、伪造回复主题和暗示不存在的合作关系。只有实际配置发送服务时才核验其当前技术要求和发送限制，不从示例复制固定限额。

## 4. 异议、情绪与成交表达

异议分析列出少量可能解释、原话线索与求证问题，不轻易断定客户在找借口。需要备选表达时，可选择共情澄清、证据说明、开放提问三种方向，分别说明适用条件和不宜使用的场景。没有真实案例时用验证方案替代案例故事。

投诉回复按“具体影响—已知事实—处理动作—负责人及更新时间—可用联系入口”组织。先解决客户遭遇，语气与事件严重程度匹配；赔付仅在已有权限和条件下提出。检查回复是否泄露隐私、甩锅或含无法兑现的时限。

临近成交时先确认需求、价值、支付或采购条件是否具备，再选一种表达：

| 表达方向 | 可用条件 | 边界 |
| --- | --- | --- |
| 确认执行细节 | 客户已明确同意购买 | 未同意前先询问是否进入确认步骤 |
| 比较两种方案 | 两种选择都真实适配 | 保留继续评估或暂不购买的选择 |
| 提醒真实节点 | 有可核验的报价期限、排期或库存 | 说明限制原因，不制造倒计时 |
| 解释保障或小范围验证 | 存在已批准保障、试用或试点 | 明示适用条件，不能创造退款保证 |
| 展示相关案例 | 案例真实、可使用且条件相关 | 说明差异，不暗示别人成功等于客户必然成功 |

通常只输出当前最合适的一版。用户要求比较或训练时再展开多版，避免把整套话术接连施加给客户。

## 5. 报价组合与可测试交付包

先核对需求、成本、交付能力、定价权限和支付条件，再设计单方案或少量套餐。需要三档时，每档都应有明确适用人群、交付物、关键差异、费用、依赖与排除项；推荐档必须说明适配理由。

比较顺序、整数或尾数价、按量或订阅、捆绑与拆分均按客群和业务验证，不视为必然有效的心理规律。单日、单席位等单位价格旁保留总费用与周期；“最受欢迎”等标记需有真实依据。对比价和限时条件必须成立。

正式报价清楚区分一次性、持续、可选与第三方费用，列修改范围、交付节点、验收与付款条件。内部毛利、让步顺序和审批红线另列为内部备忘，不混入客户报价单。

对服务类业务，将泛化服务改为可测试交付包：客户输入、要改变的一个流程、明确产物、验证方法、周期、修改次数及不包含内容。费用用实际工作量和授权定价核算，不照搬其他业务的测试价。

对材料不齐或结果不可验证的项目，先缩小诊断范围并补齐输入；不能用 AI 猜测代替客户业务判断。区分承诺交付物、目标改善与不受自身控制的最终结果。

## 6. 销售内容与团队赋能

先确定买家角色、商机阶段、客户此刻的问题和希望促成的动作，再从已确认产品事实中构建信息。可按 DECAF 拆分主题、澄清要素、连接问题与证据、排序、收敛成品；不把方法论分析代替用户要用的文案。

按需要选择内容类型：

| 类型 | 必须解决的问题 |
| --- | --- |
| 角色消息地图 | 该角色在乎什么、怎样衡量、用什么证据回应 |
| 竞品作战卡 | 客户比较标准、真实差异、已知限制、适合与不适合的场景 |
| 商机发现简报 | 本次会谈目标、事实、假设、关键问题和下一步 |
| 异议应答卡 | 可用回应、支持证据、适用条件和需升级的未知项 |
| 活动线索交接单 | 触发事件、对方表达、联系许可、承接人和反馈状态 |
| 内容维护卡 | 产品版本、适用范围、负责人、审阅状态和更新条件 |

团队使用时按其既有流程核对事实与品牌口径，区分草稿、可用和停用版本。没有审阅要求的简单改写不人为增加审批；涉及新的技术或商业承诺时找对应负责人核实。

按实际销售阶段记录内容的使用、客户反馈和机会推进，定期修订。不把下载次数或发送次数直接解释为内容带来的成交。

## 7. 客户健康、复购与唤醒

客户健康同时观察使用或服务采用、有效互动、支持问题、关键关系；风险还需看预算、合同与商业变化。分别给现状、较上期变化、影响和干预动作，不用一个总分掩盖关键故障。

需要量化评分时，先定义各指标的尺度、方向、权重和阈值，按客群校准；缺失项保留并报告覆盖率，不当作零分。健康分、风险分与续约概率含义不同；确定性加权分不称作预测模型。

扩展机会区分现有产品升级、新产品或模块、更多席位或部门。先核实当前价值、未满足需求和交付条件；高使用率或未购买某模块只是验证线索，不自动构成增购需求。

复购计划围绕产品消耗周期、服务节点、合同和客户实际使用设置触发。先关怀和补足使用价值，再提出复购。沉睡客户先区分无需求、未获价值、体验问题和触达失效，按分层安排唤醒；有投诉先处理问题。

唤醒文案结合真实购买或服务经历，按关怀、相关新价值、已授权权益选择内容，设置无回应或拒绝后的收尾条件。优惠、赠品和转介绍激励先算成本，不能默认有权限发放。

在客户主动认可成果且关系合适时征询转介绍，提供便于其自愿转发的简短介绍。新联系人直接提供资料或明确同意引介后再承接，不索取无必要的私人名单。

## 8. 客户问题库与持续改进

将真实咨询与交付反馈整理为脱敏的问题记录：原话、角色与场景、当前做法、具体卡点、已有材料、业务边界、可交付结果、异议、实际结果和可使用范围。不需要为积累问题模式保留客户身份。

积累后按重复程度、业务影响、材料可得性和可验证性聚类，挑适合的小范围方案。把高频问题转为诊断、交付包或有用内容，再将客户反馈、返工原因与复购线索写回问题记录。需求重复不直接证明预算或市场规模。
