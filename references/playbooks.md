# 销售场景手册

根据任务阅读相关部分：A 获客；B 需求与决策；C 价值销售；D 异议；E 谈判成交；F 技术与远程销售；G 客户经营；H 首席助理运营；I 复盘与陪练。

## A. 客户开发与会前准备

1. 从已知赢单、流失或实际服务经验定义理想客户画像（ICP）：业务场景、规模、问题、采购条件、交付适配与排除条件。没有历史数据时标注“待验证画像”。
2. 搜集与本次接触相关的公开资料或用户授权数据。优先看公司披露、官网、招聘和客户直接表达；每条信号记录来源、发生日期及与产品的关系。不要编造姓名、邮箱或联系方式。
3. 区分匹配度与购买意向。符合行业画像、访问页面或下载资料只能支持进一步了解；明确提出需求、询价或同意评估才是更直接的信号。无资料标“未知”，不等于低意向。
4. 用“适配理由、当前触发、可能顾虑、验证问题、接触对象”排序线索。只有用户需要评分且有依据时才设计分值；说明权重为工作假设，不能当真实成交概率。
5. 结合陌拜、电销、渠道转介或线上来源设计开场。渠道线索先确认归属与合作约定，避免冲突；电话先说明身份、来意和预计用时。

外联结构：**可核验的相关背景 → 待验证的业务问题 → 一条有依据的价值 → 容易回应的下一步**。缺少背景时用中性求证，不能伪装成熟人或声称已了解内部问题。

会前准备只保留：本次目标、已知事实、待证假设、关键提问、受众关切和理想下一步。不把完整公司百科当成拜访计划。

线索清单至少说明公司或客户代号、适配理由、需求信号、拟接触角色、切入点和待核实项。批量线索需要分层、标签或冷邮件序列时，转到 [转化与客户运营手册](conversion-workflows.md)。

## B. 需求挖掘与决策链

先问具体流程或最近一次事件，再沿客户的回答展开。SPIN 是组织问题的工具，不是逐项盘问清单。

| 类型 | 要获得的信息 | 可调整的问法 |
| --- | --- | --- |
| Situation 现状 | 流程、参与者、系统、业务量 | “能带我走一遍最近一次处理这件事的过程吗？” |
| Problem 问题 | 卡点、频率、已尝试办法 | “哪一步最常耽误进度？最近一次是什么情况？” |
| Implication 影响 | 成本、收入、风险、连带部门 | “这会影响哪些交付或指标？目前怎么估算影响？” |
| Need-payoff 改善价值 | 目标、优先级、成功标准 | “如果改善，您希望先看到哪个变化？怎样才算值得投入？” |

客户回答后先复述，再问一项最影响判断的缺口。把“想要一个功能”进一步连接到使用场景和结果，但不要预设该功能必然解决问题。

对复杂 ToB 商机，可按 MEDDPICC 补齐证据：

| 维度 | 要验证的事实 |
| --- | --- |
| Metrics 价值指标 | 当前基线、目标、衡量人和数据来源 |
| Economic Buyer 经济决策者 | 谁控制预算，谁能最终批准，是否有直接或可信的接触路径 |
| Decision Criteria 决策标准 | 客户怎样比较方案，哪些是必须项，谁定义标准 |
| Decision Process 决策流程 | 谁评估、谁批准、各环节顺序及客户确认的时间 |
| Paper Process 采购签约流程 | 采购、法务、安全、供应商准入、合同与付款条件 |
| Identify Pain 关键痛点 | 不解决的具体影响、紧迫性的真实原因 |
| Champion 内部支持者 | 是否有影响力，是否实际推动内部行动，而非只是态度友好 |
| Competition 替代选择 | 竞品、自建、沿用现状、推迟采购及各自理由 |

每项记录“已确认 / 有线索 / 未知”及证据，不因填满框架就认定合格。ToC 或短周期交易通常只需弄清需求、支付能力、使用条件、顾虑及购买时机。

## C. 价值呈现与商业论证

以客户已确认的优先问题组织方案：**问题与基线 → 目标 → 对应能力 → 作用机制 → 验证证据 → 成本与实施条件 → 下一步**。

- 每项能力说明怎样改变客户流程；没有直接关系的功能不进入主要叙事。
- 证据可来自产品文件、可复现演示、经许可的真实案例或客户试点。区分“已验证结果”“模型估算”“实施后待验证目标”。
- 竞品比较统一版本、日期、范围和计价条件，包含客户沿用现状的选择。未知项如实保留，不凭印象填写。
- 按 [收入与数据口径](revenue-metrics.md) 计算 ROI、TCO 与回收期。没有输入时提供变量和取数问题，不伪造精确收益。
- 需要多档方案时按实际能力、服务范围与适用条件形成可比较选项，明确一次性费用、持续费用、排除项和交付依赖。不要制造没有真实用途的陪衬套餐。

## D. 异议处理

使用 LAER：倾听（Listen）→ 承接（Acknowledge）→ 探索（Explore）→ 回应（Respond），回应后再确认顾虑是否解决。

| 客户表达 | 先区分什么 | 回应方向与可验证下一步 |
| --- | --- | --- |
| “太贵了” | 总价超限、现金流、竞品比较，还是价值未证明 | 澄清比较口径；核实范围与价值；必要时调整范围或讨论授权内付款条件 |
| “没预算” | 没有预算、预算归属不明，还是不愿优先投入 | 了解预算周期与负责人；若有真实价值再协助内部论证；条件不具备时约定重访或暂停 |
| “以后再说” | 缺少优先级、外部条件未满足，还是委婉拒绝 | 询问触发重新评估的条件；给客户明确退出选项，不虚构最后机会 |
| “已有供应商” | 合同约束、切换风险、满意度或关系惯性 | 尊重现状，了解未满足场景与续约窗口；仅在有差异时提出补充评估 |
| “不信效果” | 证据不足、迁移风险、适配或交付不确定 | 提供可核验证据或有边界试点，预先约定成功与失败条件 |
| “我要和老板商量” | 内部正常流程、支持材料不足，还是权限不清 | 提供供其内部使用的简版材料，了解评估者关注点，征询是否需要共同沟通 |

保留客户原话，不把所有拒绝解释为“隐藏购买信号”。通常先给一版自然回应和一项澄清问题；用户要求时再提供不同强度或渠道版本。

对愤怒客户：承认已发生的影响，复述事实，明确当前能做的处理与更新时间。责任未核实时不甩锅，也不先承诺赔偿、退款或未来能力。

## E. 跟进、谈判与成交

跟进必须带来新价值：补答关键问题、提供相关证据、确认决策变化或完成约定任务。以客户同意的渠道、时间和频率为准；无约定时给建议节奏并注明待沟通。无回应不自动等于许可持续触达。

谈判前确认：客户核心利益、自己已获授权的报价与让步边界、可交换条件、交付可行性，以及谈不成时的替代方案。缺少底价或授权时不自作主张设定。

将让步写为有条件的交换方案，例如“若缩小到已确认的试点范围，可重新核算费用”，而不是未经批准承诺折扣。保持关键条款透明，不能把未确定的功能路线图作为合同保证。

对临近成交的复杂商机，拟议双方行动计划（MAP）：业务或技术验收、经济决策、采购与法务、签署、付款、交接。每项含双方负责人、目标日期、依赖与完成证据；未获客户确认前不写成已同意。

成交信号应来自客户行动，如提供评估数据、安排关键人、确认预算或启动采购。口头称赞、索取报价和参加演示各有价值，但不足以单独证明即将签约。

收尾时复述已达成事项与未解决项，提出一个适合当前阶段的决策请求。条件不满足时给继续验证、调整范围、延后或退出的选择。

需要具体跟进分支、报价卡或不同成交表达时，按 [转化与客户运营手册](conversion-workflows.md) 选择；正式报价与内部让步空间分开呈现，不把内部底价发给客户。

## F. 远程销售、演示、PoC 与 RFP

- **在线会议**：确认参会者、目标与时区；提前准备议程、必要资料和连接替代方案。录音、转录使用用户提供或已获适当许可的材料。
- **演示**：围绕客户的实际任务展示“输入—操作—输出—业务意义”。在关键节点请对方验证是否贴近流程，预备截图或录像等替代材料，不堆砌功能。
- **PoC / 试点**：先写业务问题、测试假设、范围与非范围、数据条件、基线、验收指标及阈值、环境与权限、双方负责人、时限和资源。阈值必须由用户或客户确认，不能拿建议阈值冒充共识。
- **试点结果**：分别报告通过、未通过和无法判断的项目，附证据和环境限制；验证失败可调整或终止。演示成功不等于生产就绪或商业 ROI 已兑现。
- **RFP / 招标问答**：逐条保留需求编号，区分强制与可选，列“已支持 / 部分支持 / 不支持 / 待确认”、证据、限制与负责人。路线图能力标为未来计划，不能当作已交付能力响应。
- **技术异议**：依据产品文件或验证结果回答；安全、集成、性能等关键未知交给相应负责人核实，不用营销话术替代技术结论。

本 Skill 可起草方案、脚本和交接要求；真实环境搭建、系统配置或部署按用户的具体任务另行处理，不自动扩展销售准备工作的范围。

## G. 客户关系与战略客户经营

成交后先交接购买原因、承诺、成功指标、关键人、限制、待办和风险。客户成功与交付团队需能区分合同义务、销售建议和未来讨论项。

续约和复购前核对实际使用、已实现价值、未解决问题、组织变化、合同节点与预算条件。满意、活跃或关系良好不能单独证明续约。

战略客户按业务单元与决策角色绘制关系地图：角色、关注指标、影响力依据、态度依据、接触状态、关系负责人和下一步。不凭头衔推定预算权，不把仅有一个联系人误当完整关系覆盖。

对进入路径不清的大客户，比较高层发起与使用团队试点两条路径的适用条件、阻力和资源依赖，选择能验证的路径。每阶段写明所需角色和客户侧完成标志；竞争策略围绕真实差异与客户标准展开。

用业务复盘对齐“目标—实际—差距—改进—下一阶段价值”。只有适配成立且交付能力具备时提出增购。转介绍以客户真实成果和自愿参与为基础。

需要客户健康趋势、RFM 分层、沉睡唤醒和复购触发时，读取 [转化与客户运营手册](conversion-workflows.md)，不要把某个固定天数当成所有产品的流失标准。

## H. 首席助理的日常运营

**个人工作排序**：综合客户影响、已约定期限、真实决策事件、价值适配和能否解除阻碍。优先事项解释“为什么现在做”，不只按金额从大到小排列；经理需要决策时列清资源或授权请求。

**每日简报**：从现有资料提炼最值得推进的少量事项、客户约定、停滞风险与待确认信息。用户未要求自动运行时，只交付本次简报，不声称会每日主动推送。

**周度经营复盘**：统一数据口径后，比较目标、已实现、预测、漏斗变化和关键缺口。区分新增、赢单、输单、延期、金额变化与数据修正；每项关键风险对应一个动作与负责人。

**跨团队协调**：明确销售需要产品、技术、财务、法务或交付解决的具体问题、截止条件与影响。起草协调材料不等于已向他人发送或已得到对方承诺。

**会议转行动**：分别提取已作出的决策、尚在讨论的建议和可执行任务。决策注明作出决定的人；任务用具体动词开头。负责人或截止时间未明确时保留待确认，不把讨论建议写成客户承诺。对外纪要删除内部底价、竞争策略和与收件人无关的敏感信息。

## I. 销售复盘与陪练

评估维度：理解与同理、倾听与澄清、价值与商业逻辑、回应与表达、下一步推进。每个结论附原话或具体行为，使用“已体现 / 部分体现 / 未体现 / 无法观察”，不要仅给没有依据的总分。

只有带说话人和可靠时间信息的材料才能计算发言时长比例；纯文本字数占比只能称字数占比。没有声音或影像时，不评价语气、音量、表情或肢体语言。

陪练先设客户角色、任务阶段和一项训练目标；背景不足时说明模拟假设。每轮只给客户的一次真实反应，等待用户回应后再继续。收尾反馈“做对的行为、可改进的具体行为、替代表达、下次验证方法”。

面对拒绝，帮助销售人员辨别可控因素与外部条件，选择一个小实验或合理退出，不把乐观等同于继续施压。复盘客户与销售行为，不做人格评判。
